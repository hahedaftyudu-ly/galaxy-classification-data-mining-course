# 数据获取与融合协议

范围：完成模板“数据获取”三项；不表示其他建模/治理/展示环节已完成。

## 来源与采集身份

1. 服务器既有SDSS×CatWISE交叉匹配星表：24个结构化字段，实际3,944,564行。
2. 服务器既有Pan-STARRS五波段FITS切图：从真实文件清单、文件名、文件属性提取半结构化JSONL元数据；部分分区另读取r波段完整FITS头。

不是把原星表另存JSON后当作新来源。原始图像继续保留于<REMOTE_HOST>，元数据和分析表存本机。

本次采集是对既有项目资料的只读导出、验证和融合。原始2022年下载链未完整重建；文件头只保留部分IRSA查询、3角秒匹配参数和SDSS输入文件名。原SDSS具体版本未经本次独立核验，不能以项目口述代替证据。采集时间记录本轮2026-11-11导出的开始/结束时间，与2022历史导出时点、图像标称MJD和文件mtime分别保存。

## 样本选择

在完整星表的source_id上执行BLAKE2b（digest_size=8），将摘要作为大端整数，对3取余为0时入选。没有按模型预测或图片质量选样。实测候选1,315,321源。遍历全部395分区，完成这组候选的元数据读取，不因达到百万而提前截断某些天区。

## 元数据分层验收

所有接受的文件元数据记录：五波段各有一个普通FITS文件；r文件大小非零且为2880字节的整数倍；文件名可提供波段/切图信息；源ID与星表关联。

header_and_file记录另通过完整primary FITS头解析、SIMPLE/二维尺寸/BITPIX检查、文件长度与声明图像大小检查、r波段标识、MJD-OBS与EXPTIME验证。解析器在最初三个分区各20图与Astropy关键字段交叉核对。

file_only记录不读取全部FITS头和像素；头字段为null，原因是未采集，不解释为观测值自然缺失，更不能填造观测日期。FITS字节长度规则也不能证明全部像素有效。

早期15万源的五波段文件全量检查，以及按类抽取300源/1500图的实际像素检查，作为单独质量证据，不能外推为本轮所有候选均通过像素检查。

## 融合规则

使用source_id作1:1内连接。校验唯一性、合法标签、坐标、有限测光、匹配距离0—3角秒，以及切图文件名中心到SDSS输入位置不超过3角秒。保存所有元数据拒绝及融合拒绝记录。source_id和source_name始终作为字符串。

主表选择模板的“≥100万有效记录”路径，不通过拆分同一份旧表来凑三张表，也不将五波段或图像增广重复计为独立源。

## 存储与资源

服务器不写文件、不安装、不训练、不使用GPU。16线程低优先级读取目录和文件属性，部分头读取使用相同只读进程。数据流经gzip压缩通过SSH传到本机；按分区原子落盘，可断点续采。主分析表采用Parquet，保留源文件哈希和日志。
